01

The reconstruction problem

Each glass plate contains three monochrome exposures recorded through different color filters. In the supplied scans, their vertical order is blue, green, red. Directly assigning these thirds to RGB produces colored double edges because the exposures do not line up.

The baseline model is a two-dimensional integer translation; the final edge-based extension also estimates fractional-pixel translations. Blue is the reference; green and red move independently. A displacement (dx, dy) means moving a channel right by dx pixels and down by dy pixels. Negative values move left or up. The output uses R, G, B channel order.

Split B / G / R→Score translations→Refine across scales→Reconstruct RGB

All 18 supplied JPEGs are used at their native resolution: 12 scans around 400 × 1024 pixels and 6 around 3740 × 9700 pixels. The latter yield roughly 12-megapixel color images. Three independently selected Library of Congress scans test the same settings on additional scenes.

Scope and evidence

Raw-intensity L2/NCC baselines and improved, standardized-intensity L2/NCC results are both retained. The final edge alignment, cropping, white-balance, and contrast stages are shown separately. All offsets and timings below come from saved experiment records. The archive does not supply ground-truth shifts, so real-image alignment quality is assessed visually, while synthetic known-shift tests check the implementation.

02

How the baseline works

1. Split and normalize

Read each image as grayscale, convert to float32 in [0, 1], and split into three equal-height slices using floor(H/3). At most two leftover rows at the bottom are discarded. No image-specific offsets or hand-tuned parameters are supplied.

2. Search one scale

For each candidate (dx, dy), compare blue at (x, y) with the moving channel at (x − dx, y − dy). Two nested displacement loops exhaustively evaluate a user-configurable window; the final low-resolution experiments use [−25, 25] on both axes. Pixel operations inside each candidate are vectorized.

L2argmin √Σ[B(x,y) − M(x−dx,y−dy)]²

The code minimizes mean squared error, which has exactly the same minimizer as L2 because every candidate uses the same number of pixels.

NCCargmax Σ(B · M) / √[ΣB² · ΣM²]

NCC is the uncentered normalized dot product specified in the assignment. It is invariant to positive multiplicative intensity changes, but not to additive offsets or arbitrary differences between color channels. Higher NCC is better; lower L2 is better. Raw scores are not directly comparable across metrics.

3. Ignore borders without changing candidate support

Scoring excludes a 12% margin on each side, enlarged when necessary so every candidate samples valid pixels. This interior scoring margin is distinct from automatic output cropping. All candidates in a search share one fixed reference region, preventing a shift from winning merely because it compares fewer pixels. Wraparound pixels from shifting never enter the score.

4. Build and traverse the pyramid

Blur with a separable [1, 4, 6, 4, 1] / 16 filter, using reflected boundaries, then retain every second sample along each axis. Repeat until the longest side is at most 256 pixels. This pyramid is implemented explicitly in NumPy. No high-level pyramid or registration function is used.

At the coarsest level, search [−15, 15] on both axes. At each finer level, double the displacement estimate and search a ±2-pixel neighborhood. Odd image dimensions are handled by the same decimation grid, whose pixel spacing doubles at every level.

5. Bound the scoring cost

At a large level, score a regular interior grid with step ceil(max(interior height, interior width)/512). Candidate shifts still change by one pixel at that level; the full-resolution channels are shifted for the final output. This bounds the samples per candidate near 512², but may miss small details between sampled pixels. The final stage is therefore full-resolution displacement refinement with sampled scoring, not a claim of exhaustive full-pixel scoring.

6. Compose without wraparound

Shift channels with NumPy roll and crop to their valid intersection. Only pixels with valid contributions from all three exposures survive. This geometric overlap crop precedes the optional image-dependent border detector.

06

A stronger pyramid search

The original raw L2 experiment exposed a brightness mismatch on 01269v, and the original sampled searches left uncertainty about one-pixel choices on large scans. Three general changes address those weaknesses without image-specific offsets or parameter overrides.

Standardize brightness before matching

PreprocessI′ = (I − μ) / max(σ, 10⁻⁶)

At each level, compute each channel’s mean μ and standard deviation σ on its 12%-trimmed interior. Apply the original L2 and NCC formulas to those standardized intensity arrays. This removes a channel-wide additive offset and positive gain from the matching signal. It cannot remove arbitrary color-dependent differences. The statistics are computed once per channel per level, not refitted for each candidate; standardized L2 and NCC are therefore not assumed to be mathematically identical.

The output colors still come from the original [0,1] channel intensities. Standardization affects the displacement estimate only. These are intensity-based L2/NCC experiments, distinct from the gradient-based extension.

Score every interior pixel

The improved searches use every valid interior pixel at every pyramid level, including native resolution. This removes the earlier regular-grid sampling approximation. A ±3 refinement window gives a little more room to correct coarse-level error, while measured runtimes remain below the assignment’s one-minute target.

Recover a peak cut off by the local window

If the best finer-level candidate lies exactly on a search-window boundary, recenter a fresh ±3 search there. Allow at most three such follow-up searches per level. This bounded rule is applied automatically to every image; it avoids accepting a visibly truncated local optimum just because the first window ended. It does not guarantee a global optimum, and it cannot rescue an intrinsically misleading brightness metric by itself.

07

A resolved failure and remaining limits

Raw L2 assumes similar brightness in corresponding pixels, an imperfect assumption for exposures recorded through different color filters. On mural 01269v, its coarse-level red-channel match locks onto the wrong location; ±2 refinements cannot escape that basin. Standardized L2 and NCC recover the same plausible alignment, without using the edge-based extension.

With the final ±25 window, single-scale L2 also chooses an incorrect red displacement at (−25, 25). The initial smaller ±15 window happened to exclude that distant match. This shows why restricting the search can hide a metric failure: a wider search is useful only when its scoring function prefers the true correspondence. The NCC baselines avoid this gross mismatch.

What a translation cannot fix

Scan 00056v retains prominent colored blotches despite structural alignment. These are not repaired by channel translation or global color correction. Moving leaves, people, and water may also differ between exposures. Small residual colored fringes can reflect a mix of integer-pixel precision, local motion, optical differences, and slight geometric distortion. No claim of exact ground-truth recovery is made.

The assignment’s Emir portrait is an illustrative difficult case, but it is not one of the 18 files in the supplied ZIP. The experiments here use the actual supplied files, including 01657u; the rubric’s “016574” appears to refer to that portrait.

08

Optional enhancements

Four optional stages are implemented with one fixed configuration. Each stage is saved separately so an improvement can be distinguished from a change in appearance.

1. Align gradients instead of raw brightness

At each pyramid level, apply the same explicit five-tap blur before computing horizontal and vertical finite differences and their magnitude, √(gx² + gy²). Smoothing reduces noise in the derivative signal. Search with full-pixel NCC and the same bounded boundary recovery. At native resolution, fit a parabola to NCC at the best integer shift and its two neighbors along each axis. Clamp each fitted correction to ±0.5 pixel; flat or nonconcave fits retain the integer coordinate. This local approximation allows fractional shifts, rendered with bilinear interpolation implemented from four integer rolls. The valid-overlap crop excludes all wrapped samples. This is an optional structural alignment, separate from the required intensity metrics.

2. Detect image borders automatically

After cropping to valid overlap, analyze a reduced grid of at most roughly 700 samples per side. Mark pixels as damaged when all channels are near black (<0.06), all are near white (>0.96), or the channel range is unusually large. The disagreement threshold adapts to the central image, with a cap of 0.35.

Search only the outer 12% for rows or columns with more than 48% marked pixels. Trim through the furthest flagged line in that band. Unlike a fixed margin crop, the detected amount varies by image and edge. The 12% limit prevents severe loss, but bright skies or dark foreground can still be mistaken for borders, and narrow artifacts can remain.

3. Apply conservative gray-world white balance

Estimate channel means from nonsaturated pixels in the central 80%. Set the target to their shared mean, constrain full correction gains to [0.8, 1.25], and apply only 35% of the correction: gain = 1 + 0.35 × (clipped gain − 1). Damping reduces the strong casts that unrestricted gray-world can introduce when a scene is naturally dominated by one color.

4. Stretch contrast

Map the global 1st and 99th intensity percentiles to 0 and 1 using the same linear transform for all channels, then clip. This avoids independent channel stretches, but may clip highlights and shadows. The resulting colors are a plausible rendering, not a historically calibrated reconstruction.

Reproduce the results

The implementation uses only Python, NumPy, and Pillow. Reproduce the alignment and all images with the commands below from the project directory:

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python run.py
python build_report.py

The website code ZIP contains source, tests, the report generator, three additional input images, and source metadata. Copy the 18 JPEGs from the supplied assignment ZIP into data/provided/ before running. The complete submission bundle also includes those supplied inputs. Measured offsets and level-by-level traces are saved in results/metrics.json and results/offsets.csv. Full-resolution outputs are saved under results/<image ID>/. To process a subset, use python run.py --only 00458u 31421v; to change the exhaustive low-resolution window, use --single-radius.

Verification

Eleven synthetic tests verify displacement signs, recovery of large shifts on odd-sized images, gain invariance, valid overlap, antialiased downsampling, restoration on flat inputs, standardized matching under both gain and brightness offset, recovery of a truncated search peak, and fractional shifts on an analytically generated continuous scene. The fractional-shift test requires each recovered coordinate to lie within 0.12 pixel of its known value. These test implementation behavior; they do not substitute for inspecting real photographs.

Real-image review includes all 18 supplied reconstructions, all three additional examples, and full-resolution detail patches of the large scans. No ground-truth alignment labels are available. Report figures use smaller JPEG previews; the saved native-resolution outputs retain the original working resolution after valid cropping.
